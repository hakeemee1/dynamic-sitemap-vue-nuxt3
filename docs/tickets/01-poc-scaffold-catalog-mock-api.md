# 01 — POC scaffold: product catalog + query-string detail route + mock API

**What to build:** A runnable Nuxt 3 app with a small product catalog served from a self-hosted mock API, and a product detail page addressed via a query-string parameter (`/products/detail?product_id=<id>`), matching the query-string routing pattern described in the spec. With only the stock `@nuxtjs/sitemap` config (no custom hook yet), the generated `/sitemap.xml` should visibly demonstrate the "before" problem: no individual product URLs are listed.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

**Context:** The Nuxt app lives in a new `app/` folder at the repo root (sibling to `docs/`), keeping the POC app separate from the spec/tickets. `app/package.json` already exists — build on it as-is, do not strip it down to a minimal set. It already reflects the real dev stack (`@nuxtjs/sitemap`, `@nuxtjs/i18n`, `@pinia/nuxt`, Tailwind v4, etc.), and keeping it intact is what makes the POC representative of the actual frontend rather than a bare-bones sandbox. New dependencies needed later (e.g. `vitest` in ticket 02) should be added on top of it, not replace it. All Nuxt commands (`nuxt dev`, etc.) run from inside `app/`.

- [ ] `nuxt dev` runs the app successfully with no errors
- [ ] A products listing page shows all mock products, sourced from a Nitro server route (e.g. `server/api/products.ts`) returning an in-memory/static JSON dataset of ~20–30 generic (non-client-identifiable) products
- [ ] `/products/detail?product_id=<id>` renders the matching product's details, reading `product_id` from the query string
- [ ] Visiting an unknown `product_id` is handled gracefully (no crash)
- [ ] `/sitemap.xml` is reachable and generated by the stock `@nuxtjs/sitemap` module with no custom `sitemap:urls` hook — it should list only top-level/static routes and contain zero individual product URLs, reproducing the "before" state from the spec
- [ ] No real client name, domain, or production URL appears anywhere in code, data, or config
